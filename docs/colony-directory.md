# Colonies and cats

The protected workspace has a colony directory at `/app/colonies`, colony details at `/app/colonies/:colonyId`, a cross-colony cat directory at `/app/cats`, and cat details at `/app/cats/:catId`. Storybook has examples under **Pages → Colonies and cats**.

The local app reads and creates colonies and cats through the authenticated directory API and D1. Storybook uses an isolated in-memory directory. Reports, review status, and tasks are saved in D1 and survive refresh. A colony needs a name; a cat needs a name and a colony. Add actions are available on the directories, a colony can add a cat with that colony preselected, and a new colony can be created within the cat form. A location can be added when creating a colony or edited from its profile. Cat profiles can be edited. No real colony location data, feeding schedule, confirmed feeding visit model, cat health record, or sterilization field is implemented.

The colony list, card, and map views share the same search and records. The cat directory offers card and map views. Cat map markers represent colony locations, not individual cat sightings. Records without coordinates remain accessible in a separate list. Map positions in the local fixtures are fictional. Urgent counts include urgent reports that are pending or waiting; they are not a claim about a colony's overall health. Open task counts include directly associated tasks, tasks associated with cats in the colony, and tasks from reports associated with that colony, regardless of report status. The latest feeding item is explicitly a report and keeps its review status. Cat-associated reports can include pending, unconfirmed matches. Each report opens the existing review flow. Colony detail links to Reports with the colony and all statuses selected.

The workspace Overview shows personal task, team task, and report review progress. The Colonies directory has one result count that responds to search; it does not repeat the workspace progress cards.

The shared RecordAvatar displays an optional cat or colony photo and otherwise uses a soft pink fallback. The fictional Pepper record uses the existing stock Unsplash cat photo; it is not a photo of a real rescue cat. Cat profiles support an optional birth date, an estimate flag, details, and an uploaded photo. Birth dates cannot be in the future. Photos accept JPEG, PNG, or WebP up to 10 MB; files larger than 1 MB are resized in the browser before saving. Cat details and photos are saved in D1 through authenticated, same-origin directory endpoints. Image reads require an active account and are not cached. Storybook keeps profile edits in memory. The location picker supports a map pin, device location, or coordinates; the existing colony and cat maps update from the saved location. Recurring feeding tasks and feeding confirmations are not implemented. The directory API requires an active account; rescue-specific membership access still needs to be designed before real locations are used.

Address search sends the user's submitted query directly to the Photon public demo service, which uses OpenStreetMap data. Searches do not run while typing. Choosing a result fills an editable address or landmark, which is saved with the colony location and shown on the profile. Moving the pin clears the previous address so it is not presented as the new location. A member can enter an address or explicitly request a nearby address for a pin; that lookup sends the pin coordinates to Photon. Existing locations without a saved address retain their coordinates until a member adds one. The public service may be unavailable or rate-limited; the map pin and coordinate fields remain usable. Set `VITE_GEOCODER_URL` at build time to use another Photon-compatible endpoint.

Colony and cat profiles share a compact action area. New report preselects the current colony and, on cat profiles, the cat. The composer allows both to be changed; changing the colony clears the cat selection. Urgent reports and the latest feeding report do not repeat in the other recent reports section. New task preselects that cat or colony and supports more related items.

When adding a cat, the member can add a colony without leaving the cat draft. The new colony is selected automatically. The small search, view switcher, and add action use matching control heights.

The cat profile checks are `tests/directory/directory.test.mjs` and `tests/ui/cat-profiles.spec.ts`.

Profiles list open and completed related tasks. An assignee or an administrator can edit, complete, or reopen a task from either profile; other members can view it. Direct associations and associations through a linked report are included.

Each cat and colony has an authenticated timeline backed by D1. It records profile and location changes, cat additions and moves, task creation and changes, and report submission and review activity. Entries keep the actor’s name and time. Profile, task, and report-review entries include changed values where available. Cat photos are recorded as changes, not copied into the history. New events are saved in the same database batch as the action. The migration adds creation entries using the existing creation metadata; earlier edits cannot be reconstructed. Storybook keeps its activity in memory for each example.
