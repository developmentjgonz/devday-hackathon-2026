# Colonies and cats

The protected workspace has a colony directory at `/app/colonies`, colony details at `/app/colonies/:colonyId`, a cross-colony cat directory at `/app/cats`, and cat details at `/app/cats/:catId`. Storybook has examples under **Pages → Colonies and cats**.

The local app reads and creates colonies and cats through the authenticated directory API and D1. Storybook uses an isolated in-memory directory. Reports, review status, and tasks are saved in D1 and survive refresh. A colony needs a name; a cat may have a colony. Add actions are available on the directories. A cat added from a colony profile belongs to that colony; its profile can be edited to move it later. A new colony can be created within the cat form on the directory. A location can be added when creating a colony or edited from its profile. Cat and colony profiles support recurring care rules, described in [My Tasks](tasks.md). No confirmed feeding visit model, cat health record, or sterilization field is implemented.

Each cat belongs to at most one colony. **Manage cats** on a colony profile can move an existing cat into that colony or remove it from the colony. Removal keeps the cat's profile, photo, reports, tasks, and history. Cats without a colony remain in the cat directory and can be added to a colony later. Colony changes appear in the cat and colony timelines. Apply `0021_cats_without_colonies.sql` to the D1 database before deploying this feature; local setup applies it automatically.

Cat creation, colony creation, membership, and location forms use a compact fixed title bar. Colony fields and record context scroll with the form. Creating a colony within a cat draft keeps the cat's fields and scroll position. Back and Escape return focus to Add colony. Membership actions keep focus inside the panel without forcing a scroll; when the last available cat is added, focus moves to the members heading. Success text appears after the form so it does not shift existing controls.

The colony list, card, and map views share the same search and records. The cat directory also offers list, card, and map views. Both directories start with compact vertical lists. List feeds append 20 local records at a time without replacing existing rows. Cat map markers represent colony locations, not individual cat sightings. On the colony map, selecting a marker opens its details drawer. The Find colony control provides keyboard access and includes colonies without coordinates. The cat map lists cats without a mapped colony separately. Map positions in the local fixtures are fictional. Urgent counts include urgent reports that are pending or waiting; they are not a claim about a colony's overall health. Open task counts include directly associated tasks, tasks associated with cats in the colony, and tasks from reports associated with that colony, regardless of report status. Cat-associated reports can include pending, unconfirmed matches. Each report opens the existing review flow. Colony detail links to Reports with the colony and all statuses selected.

**Colony bubbles** opens `/app/colonies/bubbles` in the protected workspace. Each colony has a circle with one linked bubble for each assigned cat. Hovering over or focusing a cat shows its name, colony, and any saved age and details. Scroll to zoom around the pointer, drag the background to pan, or use the zoom controls and Fit all. On touch screens, scroll the chart to move it. The background circles drift gently; motion pauses during interaction and is disabled for reduced-motion preferences. The Map view uses the same colony records and their saved locations. Cats without a colony appear separately in the bubble view. Storybook includes fictional empty and large-group examples.

Local setup adds a fictional community of 25 colonies and 200 cats to a fresh database. The community seed uses approximate neighborhood centers from the [City of Miami neighborhood map](https://gis.miami.gov/gis/rest/services/Maps/Neighborhoods/MapServer); they are not real colony locations. Existing records and edits are preserved, so the total can be higher. `npm run db:seed:community` adds the community to an existing local setup. Most fixture cats use generated portraits; the existing Pepper fixture uses a stock image. The seed is never applied to a remote database.

The workspace Overview shows personal task, team task, and report review progress. The Colonies directory has one result count that responds to search; it does not repeat the workspace progress cards.

The shared RecordAvatar displays an optional cat or colony photo and otherwise uses a soft pink fallback. The fictional Pepper record uses the existing stock Unsplash cat photo; it is not a photo of a real rescue cat. Cat profiles support an optional birth date, an estimate flag, details, and an uploaded photo. Birth dates cannot be in the future. Photos accept JPEG, PNG, or WebP up to 10 MB; files larger than 1 MB are resized in the browser before saving. Cat details and photos are saved in D1 through authenticated, same-origin directory endpoints. Image reads require an active account and are not cached. Storybook keeps profile edits in memory. The location picker supports a map pin, device location, or coordinates; the existing colony and cat maps update from the saved location. Recurring feeding tasks and feeding confirmations are not implemented. The directory API requires an active account; rescue-specific membership access still needs to be designed before real locations are used.

Address search sends queries to the Photon public demo service, which uses OpenStreetMap data. Suggestions start after at least three characters and a short pause in typing. A result must be selected before the search changes the pin or can be saved. The selected address appears in the search field. Coordinates and manual address edits are available under address details. Moving the pin clears the previous address. A member can explicitly request a nearby address for a pin; that lookup sends the pin coordinates to Photon. Existing locations without a saved address retain their coordinates until a member adds one. The public service may be unavailable or rate-limited; the map pin and coordinate fields remain usable. Set `VITE_GEOCODER_URL` at build time to use another Photon-compatible endpoint.

Colony and cat profiles share a compact action area. New report preselects the current colony and, on cat profiles, the cat. The composer allows both to be changed; changing the colony clears the cat selection. On wider screens, colony profiles show open tasks beside the location map. Open reports include reports that need review or are waiting for details, with urgent reports first. All urgent reports are shown, followed by recent non-urgent reports up to five items in total. A link opens all colony reports, including reviewed reports. New task preselects that cat or colony and supports more related items.

Profiles list open and completed related tasks. Completed tasks are collapsed under a count and can be expanded. An assignee or an administrator can edit, complete, or reopen a task from either profile; other members can view it. Direct associations and associations through a linked report are included.

Each cat and colony has an authenticated timeline backed by D1. It records profile and location changes, cat additions and moves, task creation and changes, and report submission and review activity. Entries keep the actor's name and time. Profile, task, and report-review entries include changed values where available. Cat photos are recorded as changes, not copied into the history; Google locations retain only their place IDs. New events are saved in the same database batch as the action. The migration adds creation entries using the existing creation metadata; earlier edits cannot be reconstructed. Storybook keeps its activity in memory for each example.

When adding a cat, the member can add a colony without leaving the cat draft. The new colony is selected automatically. The small search, view switcher, and add action use matching control heights.

Cat creation and profile editing keep the colony and cat at the top of the drawer. The cat name follows the current draft. When a colony is added within a cat draft, both draft names remain visible. Colony location and cat-management drawers show their colony in the same position. These links stay visible as the remaining fields scroll.
