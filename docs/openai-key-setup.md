# OpenAI API key setup

An administrator can save an OpenAI API key in **Configuration → AI analysis**. The key is stored for later use. Saving it does not make an API request or enable report analysis.

## Local development

1. Start the app with `npm run dev` and open `http://127.0.0.1:5197/sign-in`.
2. Sign in as the local administrator and open **Configuration → AI analysis**.
3. Create a key for the Mews project in [OpenAI Platform](https://platform.openai.com/api-keys). Use a separate key for local development. A restricted key with write access to Responses is suitable for a future Responses API integration; update its permissions if the integration needs other endpoints.
4. Paste the key into **OpenAI API key** and select **Save changes**. Choose a model when the report analysis integration is ready.

The page shows whether a key is saved, but never displays the saved value. The app encrypts the key before storing it in local D1. The local encryption key is generated by `npm run dev:api` and must stay stable while the encrypted key is in use. See [administrator configuration](configuration.md) for storage details and recovery.

## Release

The local database and secrets are separate from the deployed environment. Before enabling a key in a release, configure a unique, stable `CONFIG_ENCRYPTION_KEY` Worker secret as described in [administrator configuration](configuration.md). Then sign in as an administrator in the deployed app and save a separate production API key. Do not put API keys in Git, browser environment variables, or documentation.

Report analysis and the review of suggested tasks, cats, and colonies are future work. Model choice, API usage, data handling, and validation should be checked when that integration is built.
