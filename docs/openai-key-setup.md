# OpenAI API key setup

An administrator can save an OpenAI API key in **Configuration → AI analysis**. Saving the key does not make an API request. When AI is available, opening an unreviewed report automatically requests suggestions.

The same page has optional [autopilot settings](autopilot.md). When autopilot is enabled, the scheduled Worker can use the saved key to review reports without an open browser. Its separate human review switch controls whether proposed changes need approval. Autopilot sends relevant directory records with the report so it can identify existing cats and colonies. Autopilot is off by default.

## Local development

1. Start the app with `npm run dev` and open `http://127.0.0.1:5197/sign-in`.
2. Sign in as the local administrator and open **Configuration → AI analysis**.
3. Create a key for the Mews project in [OpenAI Platform](https://platform.openai.com/api-keys). Use a separate key for local development. A restricted key needs write access to Responses and audio transcription to analyze reports and recordings.
4. Paste the key into **OpenAI API key** and select **Save changes**. Leave the model blank to use `gpt-4.1-mini`, or enter another model that supports structured outputs, images, and file inputs in the Responses API.

The page shows whether a key is saved, but never displays the saved value. The app encrypts the key before storing it in local D1. The local encryption key is generated by `npm run dev:api` and must stay stable while the encrypted key is in use. See [administrator configuration](configuration.md) for storage details and recovery.

## Release

The local database and secrets are separate from the deployed environment. Before enabling a key in a release, configure a unique, stable `CONFIG_ENCRYPTION_KEY` Worker secret as described in [administrator configuration](configuration.md), and deploy the `AI_ANALYSIS_RATE_LIMITER` binding from `wrangler.jsonc`. Then sign in as an administrator in the deployed app and save a separate production API key. Do not put API keys in Git, browser environment variables, or documentation.

When a reviewer opens an unreviewed report, the app sends the report title, text, date, linked cat and colony names, and up to 20 linked task titles to OpenAI. To check for duplicate reports, it also sends the title, text, date, and linked cat name of up to 20 related reports from the same saved colony. It does not send reporter details or the rest of the directory. The selected report's supported attachments are included: JPEG, PNG, GIF and WebP images; PDF, text, CSV and Word files; and supported audio recordings. Audio is first sent to OpenAI's transcription endpoint, and the transcript is included in the analysis. The review lists attachments that could not be fully analyzed. AVIF images, unsupported audio formats, missing files, and attachments beyond a total of 25 MB cannot be included. Text and CSV files are decoded as UTF-8 and included as text. Long text files and transcripts are limited to their first 40,000 characters. Public report chat uses the same preparation when visitors send files for review, before they confirm submission. Supported recordings include MP3, MP4/M4A, WAV, WebM, OGG, and FLAC. Report text and attachments may contain personal information. The Responses request uses `store: false`; see OpenAI's [data controls](https://developers.openai.com/api/docs/guides/your-data) for other retention rules.

Suggestions stay in the open browser session and are not saved as records. A reviewer can dismiss a suggestion, approve a task assigned to themselves and linked to the selected colony and cat, edit and create a suggested task, cat, or colony, or compare a possible duplicate before linking it. The duplicate check examines a bounded set of text matches and recent reports about the same cat, so it can miss matches. It never links reports automatically. Check for existing cat and colony records first; the app filters exact matches to linked records, but this is not a complete duplicate check. No records are created until the reviewer approves a task or submits a form. The analysis has a five-requests-per-minute workspace limit and is unavailable to deployed demo accounts. API calls use the project's OpenAI billing and limits.
